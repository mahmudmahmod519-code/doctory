# DATABASE DOCUMENTATION

## Overview

This document describes the database schema for the Doctory AI-Powered Smart Clinic System. The database uses **MongoDB** (document database) via **Mongoose** ODM. It contains **11 collections** to manage users, doctors, bookings, reviews, reports, notifications, audit logs, data deletion requests, refresh tokens, and more.

> **Important:** This is a **MongoDB** project, not MySQL. Do not use SQL syntax or TypeORM. All schemas are defined with Mongoose in `models/*.entity.js`.

## 🗄️ How to Use

### 1. Create Database and Collections

MongoDB is schemaless, but Mongoose enforces schema validation at the application level. Run the migration script to ensure all indexes are created:

```bash
# Connect to MongoDB (must be running)
npm run migrate
```

This imports all model files, which triggers Mongoose to create the defined indexes on each collection.

### 2. Seed Sample Data (Optional)

```bash
# Seed with sample admin, doctors, patients, bookings, reviews, reports, notifications
npm run seed
```

The seed script is idempotent — if users already exist, it skips seeding to avoid duplicates.

### 3. Verify Collections

```bash
# Connect to MongoDB shell
mongosh --quiet --eval "db.getCollectionNames()"

# View all users
db.users.find().limit(5)

# View bookings for a specific doctor
db.bookings.find({ portfolio_id: ObjectId("...") })

# View waiting queue for a booking
db.bookingitems.find({ booking_id: ObjectId("...") }).sort({ queue_number: 1 })
```

## 🔄 Migrations

npm run migrate

## ⚠️ Important Notes

1. **No MySQL / TypeORM:** This project uses MongoDB with Mongoose exclusively. The old MySQL schema and TypeORM entities have been removed.
2. **Soft Delete:** Collections that support soft delete (`users`, `bookings`, `bookingitems`, `doctorworks`) use `deleted_at` / `deleted_by` fields. Queries should filter out documents where `deleted_at` is not null.
3. **UUIDs vs ObjectIds:** External-facing IDs (`user_id`, `portfolio_id`, `work_id`, `notification_id`) are UUID strings stored as strings. Internal MongoDB references (`_id`, `portfolio_id` in child collections) use `ObjectId`.
4. **TTL Index:** The `refresh_tokens` collection has a TTL index on `expires_at`, so expired tokens are automatically deleted by MongoDB.
5. **Character Set:** MongoDB natively supports UTF-8, so Arabic text is supported without special configuration.
6. **Indexes:** All collections have indexes defined in their Mongoose schemas. Run `npm run migrate` to ensure they are created.
